## LAB 04 — LINUX SERVICE DISCOVERY & AUDITING

Date: 05/11/2026

**Goal:**
Identify listening TCP services, examine port states and compare Nmap 
scans with local system information.

**Part 1 — Baseline Scanning**
- Used `sudo ss -ltnp` to inspect listening TCP sockets.
- Scanned localhost (127.0.0.1) with Nmap.
- Examined port 8080 before starting a service.

**Part 2 — Service Discovery**
- Started a Python HTTP server on port 8080.
- Used `nmap -sT -sV -p 8080 127.0.0.1`.
- Confirmed port 8080 was open while the service ran.
- Used `ss` to investigate local listening processes.

**Part 3 — Verification & Evidence**
- Stopped the Python HTTP server.
- Rescanned port 8080 and confirmed it was closed.
- Saved Nmap scan results and listening socket information.

**Key Learning:**
- Open = a service is accepting TCP connections.
- Closed = target reachable, but no service listening.
- Filtered = filtering prevents Nmap determining port state.
- `ss` inspects local sockets and associated processes.
- Nmap examines network accessibility and services.
- Opening or stopping a service changes port visibility.
- A listening service may increase a system's attack surface.
- Service names based on ports don't confirm actual software.

**Result:**
Successfully demonstrated open/closed TCP port states by starting and 
stopping a controlled HTTP service.

## LAB 05 — TCP & HTTP PACKET ANALYSIS

Date: 05/11/2026

**Goal:**
Capture and analyse TCP traffic to understand connection establishment,
 data transfer and termination.

**Part 1 — Packet Capture**
- Started a Python HTTP server on localhost port 8080.
- Used tcpdump to capture TCP traffic on the loopback interface.
- Generated HTTP traffic using curl.
- Saved packet capture as tcp-handshake.pcap.

**Part 2 — TCP Analysis**
- Opened the capture in Wireshark.
- Identified SYN → SYN-ACK → ACK handshake.
- Examined source/destination IP addresses and ports.
- Analysed TCP sequence and acknowledgement numbers.
- Identified HTTP GET requests and 200 OK responses.
- Observed FIN/ACK packets terminating connections.

**Part 3 — Findings**
- Captured three TCP connections using different client ports.
- Server consistently listened on TCP port 8080.
- Confirmed SYN consumes one TCP sequence number.
- Examined how TCP uses acknowledgements for reliability.

**Key Learning:**
- TCP establishes connections using a three-way handshake.
- Sequence numbers track bytes transmitted.
- ACK numbers identify the next expected byte.
- Clients use temporary source ports for connections.
- Wireshark enables detailed protocol analysis.
- tcpdump captures traffic directly from Linux interfaces.
- HTTP traffic is readable because it is unencrypted.

**Result:**
Successfully captured and analysed TCP connection establishment, 
HTTP communication and connection termination.

**Evidence:** Original capture: `tcp-handshake.pcap`; screenshots and capture await review before publication.

## LAB 06 — LINUX SYSTEM HARDENING

Date: 06/11/2026

**Goal:**
Practise Linux permissions, user management, access control and
service auditing.

**Part 1 — File Permissions**
- Created confidential and public test files.
- Configured permissions using chmod (600, 644).
- Verified permissions and ownership using stat.

**Part 2 — Users & Groups**
- Created test users Alice and Bob.
- Created staff-secure group and added Alice.
- Configured file ownership using chown.
- Applied 640 permissions to confidential records.
- Confirmed Alice could read the file while Bob was denied.

**Part 3 — Least Privilege**
- Explored owner, group and others permissions.
- Restricted group access to read-only.
- Demonstrated group-based access restrictions.

**Part 4 — Service Auditing**
- Used ss -ltnp to inspect listening TCP services.
- Identified Python HTTP server on 127.0.0.1:8080.
- Investigated DNS-related listener on port 53.
- Stopped the HTTP test server and verified its removal.
- Inspected Linux DNS configuration.

**Key Learning:**
- chmod controls file access permissions.
- chown changes file ownership.
- Group membership determines group-level access.
- Least privilege limits unnecessary permissions.
- Listening ports can expose network services.
- Local binding addresses affect network exposure.
- ss identifies sockets and associated processes.

**Result:**
Successfully demonstrated Linux access restrictions and basic service
auditing.

**Limitation:** A TCP/53 listener was observed, but its owning service was not confirmed. Permissions screenshots await review before publication.
